Button

Compose three classes in markup: the base .btn, one color variant, and one size — class="btn btn-primary btn-md". The base ships layout, radius and transition but deliberately no color, so a variant is what makes a button visible.

Sizes × variants

Sizes are not cumulative with the base's own padding — they override it by source order, so exactly one size class should be present.

With icons

.btn already lays out an .icon beside its label with gap-2 — no wrapper element and no extra spacing utility. Position is decided by where you put the icon in the markup.

Icon only

The base is justify-center, so a lone icon centres itself. There is no visible label, which makes aria-label mandatory rather than optional.

States and edges

Disabled

Built into the base: disabled:opacity-50 plus disabled:pointer-events-none, so no variant needs its own disabled rule.

Base with no variant

Intentional: component classes here are compositional, never one custom class @apply-ing another. So .btn alone is shape without color — useful as a starting point for a one-off, and a reminder that the variant does the visual work.

On an anchor

.btn is inline-flex and element-agnostic — it looks the same on a <button> or an <a>. This one really navigates.
